# Ordinary-class guided rockets, BF2

2026-10-28, GUIDED, [O] UNAUDITED. This investigation used the local PS2 class data, executable and existing research. No live PCSX2 comparison was performed. `analysis/INDEX.md` was read first; relevant existing notes are `re-remote-droid.md`, `re-vehicles.md` section 4.2, `re-vehicle-death.md` section 4 and `re-boundary.md` section 4.

## Census and scope [D]

The locally baked BF1 side databases have no remote weapon firing a flyer. BF2's ordinary soldiers carry four award weapons: `all_weap_award_rocket_launcher`, `cis_weap_award_rocket_launcher`, `imp_weap_award_rocket_launcher`, `rep_weap_award_rocket_launcher`. All fire `com_weap_award_rocket_launcher_ord`, an entity whose engine base is `flyer`, through the `remote` weapon base. This is neither a homing missile nor a recon droid.

Carrying records, including four inheritance templates:

| Faction | Soldier records |
| --- | --- |
| Rebels | all_inf_default_rocketeer, all_inf_rocketeer, all_inf_rocketeer_fleet, all_inf_rocketeer_jungle, all_inf_rocketeer_snow |
| CIS | cis_inf_default_rocketeer, cis_inf_rocketeer |
| Empire | imp_inf_default_rocketeer, imp_inf_rocketeer, imp_inf_rocketeer_snow |
| Republic | rep_inf_default_rocketeer, rep_inf_ep2_rocketeer, rep_inf_ep2_rocketeer_chaingun, rep_inf_ep3_rocketeer |

The concrete classes are Rebel Vanguards, Assault Droids, Shock Troopers and Clone Heavy Troopers and their listed variants. The local integration test repeats the inherited-slot census, checks every weapon and launches every record. Chewbacca's hero launcher and turret guided weapons are outside this implementation. The TIE bomber's copilot rocket (`imp_weap_fly_tiebomber_guided_rocket`, ord `com_weap_veh_fly_guided_rocket_ord`, spawn offset 0 -3 20 on TURRET1) runs as a seat rocket on the same path. Their runtime loaders remain unsupported, as before, instead of changing their behavior through the new infantry path.

These weapons author `MedalsTypeToUnlock = 2`. The maintainer explicitly chose to keep medal progression separate and use the existing award session cheat. Since #142 every award weapon is in the roster and follows one rule (`Sim::weapon_locked`, re-grenades.md §2.4): cycling, firing and the bots' weapon choice skip it until its unit holds the medal. Only the pause cheat or CLI `--cheat awards` grants medals, and only to the player outside the space modes, so bots no longer launch award rockets with the cheat on. The standard launcher authors no `MedalsTypeToLock`, so the guided one is an extra slot, not a replacement. No medal-earning or profile progression is implied (#130).

## Disc properties [D]

Shared ordinary award rocket: MaxHealth 1, HealthType droid, EnergyBar 200, EnergyAutoRestore -5, EnergyBoostDrain 20, Acceleraton 80, Min/Mid/MaxSpeed all 30, BoostSpeed 80, BoostAcceleration 50, PitchRate/TurnRate 1.2, PitchFilter/TurnFilter 4, their deceleration-filter hashes 53d5cdc8/1795170d both 4, BankAngle 0.1, BankFilter 3.5. The weapon has one round per clip; authored class totals are Rebel 5, other sides 4. InitialSalvoDelay 0.3, ShotDelay 1.4, ReloadTime 0.0. The spawn offset hash 389c8e46 is (-0.5, 1, 5). Geometry is `com_weap_missile`; the authored bank is bazooka.

The ordinary missile uses TrackCenter (0,1,-3), TrackOffset (0,2,6). EngineSound is `rep_inf_grocket_engine_parameterized`, DeathSound `imp_weap_ord_exp_lg`. Exhaust effect hash 0894d756 names `com_sfx_exhaust_jedistarfighter`; it already exists in the common BF2 effect bake. The missing model was baked directly from the local INGAME.LVL: 95 vertices, 52 triangles, texture `missile`. `rebake.sh` now includes this model in its persistent side bake list.

Two explosion bindings are distinct: e04f08c1 = `com_weap_veh_guided_rocket_exp` (500 damage, DamageRadius 22.5, vehicle/building scale 0.2), 8a323f32 = `com_weap_veh_guided_rocket_noncrit_exp` (50 damage, inner/outer 3/5, vehicle scale 0.5). Effects, pushes, per-target scales and sounds are read through the existing explosion loader and damage path.

## Executable evidence [O]

- `FUN_003465f8` derives the remote weapon class from the dispenser. `FUN_00346480` records the spawned controllable and transfers the soldier's controller to it when class+4c0 is set. `FUN_00346380` / `FUN_003463f8` forbid a second spawn while that reference remains valid. `FUN_00346100` handles the fresh control press and a second trigger-word kill path; `FUN_00345fe8` destroys the remote on weapon destruction.
- `FUN_0020fd58` loads the flyer movement properties and explosion bindings. Property c6e9c80b sets the guided flag in class+1208 and remote pilot type 3. `re-boundary.md` independently identifies the three flyer ordnance families using it.
- `FUN_00202d08` handles this guided flag before ordinary flyer movement (B2:115923-116010). With a controller, energy (`+0x1a2`) above 0 and the end timer `+0x19e` at 0 it runs the ordinary flyer update, the same one a piloted ship runs. Otherwise it detonates: critical (class+0xed8) when BoostSpeed (+0x840) is above 0, a controller is attached and forward speed (`+0x199`) is at least BoostSpeed times class+1244 (authored bb3082af = 0.8), else noncritical (+0xedc). The first such frame explodes and adds dt to `+0x19e`. While `+0x19e` is at most class+1238 and the controller stays attached, the spent rocket holds still and keeps control; after that, or at once without a controller, it is removed. A rocket cannot be parked and retaken like the recon droid.
- In the Flying phase the only guided difference is that the jump toggle cannot start a landing (B2:117199). Death by health goes to phase 4 with `+0x19e` = 600 when the class has no chunk slots (`FUN_00215f80`), so the rocket is removed on the next frame (B2:116895-116929).
- Spawn: the flyer constructor `FUN_001fff10` (B2:113803) calls `FUN_00200b50` for guided classes (B2:114155-114192). That sets phase Flying, lift 1, velocity forward times `FUN_00202cc0`, which is MinSpeed (+0x834, hash fbe2eb62, B2:125143), crash timer 0, energy to EnergyBar (class+0xe04), and the level timer to 1.
- End-hold class fields and their defaults (B2:123764-123766), with their loader hashes (B2:124350, B2:124842, B2:124859, B2:124964): 9bdfa490 sets class+1238 (hold time, 1.0 s), 962e0745 sets class+123c (back-off speed, 60 m/s), 325bf479 sets class+1240 (back-off distance, 20 m), bb3082af sets class+1244 (critical factor, 0.8). The award ord authors all four: 1.0, 60, 20, 0.8.
- Camera, `FUN_0020d450`: a live rocket takes the ordinary flyer camera path, using its ord's TrackCenter, Slow/FastOffset, FastFOV and MoveTension with the lag of `FUN_001cef68`. A spent rocket (no controller, energy ≤ 0, or `+0x19e` ≠ 0) holds the camera. Each frame it moves the camera along the rocket's -forward (entity row 2) at class+123c × dt while (camera − rocket)·(−forward) is under class+1240, unless a collision ray blocks it (B2:122322-122400).
- Contact, `FUN_0020bff8` (B2:121489-121552): a guided flyer that touches something is pushed out along the contact normal by the depth. If its energy (`+0x1a2`) is above 0 and the other object takes damage (its virtual +0x3c), it deals contact damage through that object's TakeDamage (virtual +0x1c on +0x22c). The amount is lerp(class+120c, class+1210, s) with s = clamp((forward speed − MaxSpeed) / (BoostSpeed − MaxSpeed), 0, 1), or class+120c when BoostSpeed ≤ 0. The scales class+1214..+1234 are all 1 for these ords. Then `FUN_001e1f48(0, +0x1a1)` sets energy to 0, so the next `FUN_00202d08` frame takes the spent path: the explosion by the speed rule, then the hold. Defaults 500 and 2000 (B2:123749-123750), hashes 376b238a and 487b2329 (B2:124373, B2:124540). `com_weap_veh_fly_guided_rocket_ord` authors 1500 and 5000. So a TIE Bomber rocket that hits at cruise (120 m/s, under 0.8 × 225) deals 1500 to what it touched, then makes the noncritical blast.
- `re-vehicle-death.md` pins health damage through the authored HealthType scale. The new rocket accepts bolts and blasts as a droid-scaled target; its own explosions credit the launching unit's generation and team through the existing blast path.

Useful reproducible reads: `python scripts/re_check.py word b2 0x629ca8 36 --u32`; extract the named `FUN_00346100`, `FUN_00346480`, `FUN_00202d08` and `FUN_0020fd58` bodies from the local corpus; check the corresponding raw instructions with `scripts/tools/eedis.py bf2 <start> <end>`. No decompiler source or disc asset is committed.

## Port controls, implementation and acceptance limits

Select the award launcher with the award cheat ("Award weapons", `--cheat awards`) on, as the player on a ground map of either game (a BF1 heavy carries BF2's launcher beside its own, award-weapons.md §3), then fire. Its windup consumes one round and launches one controlled rocket. Right stick or mouse steers; forward stick selects throttle; sprint boosts. The common remote pad-consumption and control-release helpers are shared with recon droids. The soldier remains stationary under control. ACTION returns control and ends the rocket with the noncritical explosion. A fresh secondary-fire press detonates it. Expiry, impact, destruction, owner death/recycling and mounting also return or clear control; held fire across return cannot accidentally launch another rocket. These ACTION and secondary-fire bindings follow the port's remote-control convention; their precise original pad mapping remains unresolved and is not claimed as PS2 validation.

Since #138 the rocket flies through the same flyer step as a piloted ship (`core::vehicle::flyer::fly`, BF2 law). Its parameters come from the ord through the shared builder `vehicle_pads::flyer_params`. The pad maps as for a pilot: left stick strafes and rolls, forward stick sets the throttle, right stick and mouse steer, and sprint boosts once the throttle is at least 0.2. Level-out, bank tilt, the velocity filter and energy drain are part of that step. A bot's rocket uses the same shaping with human, boost and jump off. It launches at MinSpeed in phase Flying. On expiry it explodes, holds for the hold time with control kept, then returns control. Impact takes the same path as `FUN_0020bff8` does. The swept contact (`Sim::guided_contact`) names what it touched. `Sim::guided_strike` deals the speed-scaled contact damage to it and sets energy to 0. On the next tick the rocket explodes by the speed rule and holds for 1 s while the camera backs off, so the player sees where it hit. ACTION, destruction and owner loss still end it at once.

The camera is the flyer chase camera, built from the ord's section (`walk::guided_section`). The ideal point is rocket + frame·TrackCenter + view·lerp(SlowOffset, FastOffset, speed/top). The eye lags toward it through MoveTension, seeded from the previous camera position, and FOV eases from ThirdPersonFOV toward FastFOV. With the award ord the ideal point is about 4 m ahead of the rocket, and the MoveTensionZ lag (about 7.5 m at 30 m/s) settles the eye about 3.5 m behind it. Piloted ships work the same way (`re-space-assault.md` §11). Once spent, the eye backs off as `FUN_0020d450` does. The reticle projects the rocket's forward line 1024 m out. Because of the BF2 view tilt it sits slightly above centre, as for ship pilots. Rockets now draw nose first, and the player sees their own rocket. The exhaust (`com_sfx_exhaust_xwing`, NoRegisterStep, re-fx.md §5.5) rides rigidly with its emitter. Its frame now follows the render-interpolated rocket, as bolt trail heads do (`Fx::drawn_round_frames`). Before this, the head sat at the sim tick's position, up to one tick ahead of the drawn model, so at 120 m/s the short flame showed in front of the rocket. Health/energy HUD, launcher animation, model, authored exhaust and parameterized engine/death/explosion audio are connected. Render interpolation restores sim state exactly, including the tilts and the held camera. A maintainer playtest exposed a full-tick prediction overriding the interpolated rotation at display rate; the follow-up regression covers 60/75/144 Hz while preserving the flight law. No lock-on is introduced. Bots choose the unlocked weapon through the existing arsenal and steer at their current visible enemy.

Boarding a flyer: `FUN_0020d450` hands `FUN_001cef68` the caller's camera matrix (its third argument) as the previous eye (B2:122628, read at B2:77742-77745, 250 m test at B2:77761) and writes the new eye back. So the pilot camera starts from wherever the last camera was and lags in through MoveTension, and it snaps only past 250 m. The port's pilot camera now does the same from the previous drawn camera (`WalkSim::next_cam_flyer`), where it used to start at the settled place. This replaces the `measure:` boarding note in `re-space-assault.md` §10.

Copilot seat, seat switch and exit. Lines are `SWBFRNT2.ELF-decomp.c`.
- A MountedTurret seat's camera is `FUN_00270018` (190339). Out of first person it calls `FUN_001cef68(dt, 1, 1, turret class+0x790, ..., camera matrix, turret matrix +0x1c0, its forward row +0x1e0, owner)` (190496). This is the same lag camera as the pilot's, fed the caller's camera matrix as the previous eye and turn. The turret matrix is the ship's entity matrix times the turret's own aim (`FUN_0026cea0`, 188921-189004), so it keeps the ship's drawn tilt. With class+0x84b set, the parent's matrix gives the up row; not traced further.
- The section at +0x790 starts from `FUN_001ce800` (77110, called by the MountedTurret ctor `FUN_00270540`): MoveTension 30 on all six, AimTension 1000, tilt 0, TrackCenter/TrackOffset 0, collision point (0, 1.5, 0). `FUN_001d0328` (78750-78830) parses the keys: TiltValue × 0.017453294, MoveTension sets all six, EyePointOffset also writes TrackCenter.
- `FUN_001cef68` (77650-78100): the turn is slerped (`FUN_0053a3e8`) from the previous camera's turn toward the target by exp(−AimTension·dt), with the target being the frame's view turned by −tilt. The eye is frame·TrackCenter + turn·TrackOffset, then the collision, then the per-axis MoveTension lag from the previous eye. The pilot's copy has AimTension FLT_MAX outside the trick roll (122660-122666; +0x660 bit 1 is set by the trick code `FUN_00208a00`/`FUN_00208a20`, 119199-119282), so a pilot's turn snaps while his eye glides.
- `imp_fly_tiebomber_sc` TURRET1 authors TrackCenter 0 0 0 (after EyePointOffset 0 3.3 4), TrackOffset 0 0 20, TiltValue −10, limits 0 0, and no tensions. So the copilot camera hangs 19.7 m behind and 3.5 m below the turret's origin, looking 10° up along the ship, and trails it at MoveTension 30 (about 1.2 m at 60 m/s). On R1 it eases from the pilot's camera at that rate and turns at once.
- The soldier's camera is the same call (`FUN_0024cd00`, 166219-166224) with BF2's soldier sections MoveTension 15 and AimTension FLT_MAX (`re-aim-assist.md` §10.6). So after leaving a seat the eye eases in from the seat's camera at 15/s and the view turns at once. Not ported: its k1 = 0.5 while the soldier state word is 2, and the same lag while walking (the port's soldier camera has none; §10.6 measured drawn = ideal in still states).

Port: `WalkSim::next_cam_gunner` / `flyer_gunner_camera` (`FlyerSection::gunner`) for every flyer gunner seat, seeded from the previous drawn camera, eye and turn. The guessed 0.4 s seat-transition smoothstep stepped once per tick, which froze the drawn camera for several display frames and then jumped; it is gone (below). `WalkSim::next_cam_exit` eases the on-foot eye from the seat's last camera at 15/s until it is within 1 mm. `camera_rotation` had roll's sign reversed against `camera_at`; it now inverts it, which also fixes the death camera's start turn on a banked ship. `cam_from` was replaced by the handover blend below.

The player camera's handover blend (maintainer playtest 2026-11-11: on the PS2, R1, boarding and exit glide for longer and along a path; ours snapped, most of all on boarding). Lines are `SWBFRNT2.ELF-decomp.c`.
- `FUN_001bb4c0` (63784-63800) sets the camera's controllable (+0xc). When it changes, +0x90 = 0, or 1 when there was none, so no blend runs. It also sets +0xc0 = 10 and clears +0x9c/+0x94. It is called from `FUN_001ba5c0` (62945-62958), `FUN_001baea8` (63768) and 76686 (with 0). The turret is its own controllable, so R1, boarding and exit all restart it.
- `FUN_001baea8` (63534 on) adds dt to +0x90 every frame (63544). The reset comes after the add, so the frame of the change runs with +0x90 = 0.
- `FUN_001bb510` (63803 on) first saves the previous camera, turn q0 and eye p0 (+0x10..+0x4c), then calls the controllable's camera virtual (+0x1c vtable +0x10) on that matrix. Then:
  - f = 2·(+0x90). The weight is w = f² unless the global at 0x600b14 or +0xc4 is set; in that case f = min(the global at 0x5fc50c, f) and w = the global at 0x5fc510. The 0x600b14 global is set at 23656 and cleared at 471672; not traced, and not ported.
  - The blend runs while f < 1 (the first 0.5 s), the zoom is 1, the controllable is not in first person, and the new eye p1 is within 30 m of p0 (900 squared). Past 30 m, +0x90 = 1 and it ends.
  - Turn: slerp(q0, q1, w) (`FUN_0053a3e8`).
  - Eye: the midpoint m = (p0 + p1)/2 is pushed along the Z row of slerp(q0, q1, 0.5) by |p1 − p0|·0.5·(1 − f). The camera's Z row points behind the view (`FUN_001bc7c0` rows right, up, −forward, as `FUN_001cef68` builds them at 77795). The eye is then p0 + (that point − p0)·f. So it travels on an arc that bows backward. Early on it barely moves (f is small), and at the end it moves half way to the seat camera each frame.
  - Then a collision ray runs from the controllable's matrix position + (0, 1.5, 0) to the eye (`FUN_00161c60`, 0x90 mask).
  - The result is written back to +0x10, so the next frame's seat camera starts from the blended camera.
  - On the frame after the blend ends, the seat camera runs from the last blended camera. So the eye catches up about one frame's MoveTension step at once; for the copilot at 60 m/s that is about 4 m over that 1/30 s.
- The blend is per frame. The PS2 draws at 30 Hz, the port's tick rate, so it runs on the tick.

Port: `WalkSim::cam_owner_now` (soldier, seat, guided rocket, droid; none while dead, on a backdrop, a death camera or a round-end shot), `next_cam_handover` and `feed_handover` in `walk/camera.rs`; `WalkSim::cam_handover` holds it.
- The first tick returns the previous camera, then the blend above.
- After it ends, one closing tick holds the seat camera itself, so the render blend eases into it rather than snapping in one drawn frame.
- `feed_handover` writes the blended eye and turn into the held pilot, copilot and rocket cameras, as the PS2 writes +0x10. The exit lag already starts from the drawn camera.
- The display blend interpolates the handover between ticks.
- This replaces the one-tick `cam_from` and the guessed 0.4 s `MEASURE_SEAT_TRANSITION_SECONDS_ON_PS2` smoothstep, which also covered tank and walker seat changes. Those now take the PS2 blend as well.
- OURS: the collision ray uses the camera blockers and the terrain sheet; the 0x90 mask is not decoded.
- Checks: `baked_spa1_bomber_seat_switch_runs_the_ps2_handover_blend` (the held first tick, the second tick's arc and turn against the formula, the 0.5 s end) and `baked_spa1_bomber_seat_switch_and_exit_draw_without_a_snap_or_a_stall` (144 Hz, no frame that jumps against both neighbours, only the first tick held).

Exhaust size: every frame the flyer update sets each exhaust effect's emitter Size from forward speed (B2:118429-118473, `FUN_00376dd8` at decomp 360794 writing emitter instance +0x18 and its siblings through +0x34; at spawn it is set to the low value, B2:115125). The instance's +0x18 is the sampled template Size (+0x50) written by `FUN_00374570` (decomp 359369), so this replaces it, it does not multiply. Per exhaust slot the class keeps low (hash f174a3f8, class+4000[i], default 1), high (c3fd784a, +0xfc0[i], default 1) and start (e97041b8, +0xfe0[i], default 0); defaults at B2:123714-123717. With top = MaxSpeed (+0x83c, 1 when 0), floor = MinSpeed + start·(top − MinSpeed) (start·top when MinSpeed is 0) and t = max(0, (speed − floor) / (max(top, BoostSpeed) − floor)), size = low + t·(high − low), with no upper clamp. The TIE Bomber rocket ord authors 0.25 / 0.75 / 0, so its flame is a quarter size at launch and three quarters at boost; ships author their own (for example 0.95 / 1.5 / 0.85). The port drew every exhaust at the sampled Size, about four times too big on the rocket, and this made the rocket look close. Port: `FlyerParams::exhaust_scale`, used by the guided trail (`Fx::follow_rounds`) and ship exhausts (`Fx::follow_flyer_exhaust`).

PS2 comparison (the maintainer's PCSX2 slot-10 state, TIE Bomber copilot seat just after launch, read from the state file only): rocket entity 0x1d18c70 (class at +0x700), forward speed at +0x664, energy +0x688, rotation rows +0x120..+0x140, position +0x150. The camera matrix at 0x1759a00 puts the eye 4.18 m behind, 0.29 m below and 0.19 m beside the rocket, about 5° tilt, so the rocket projects to a 16 px dot. That eye may still be gliding in from the copilot view (TURRET1 TrackOffset 0 0 20). The port's camera for the same ord settles about 3.4 m behind and 0.55 m below at fov_y 56.8°, the same distance and vertical FOV. A 16:9 screen does not bring the camera closer: the port keeps the vertical FOV and widens the horizontal one, so it shows more to each side at the same size.

Not verified for #138: there was no live PCSX2 comparison of the rocket camera or flight feel. Seeding the first chase-camera frame from the previous camera follows `FUN_001cef68`'s in/out camera matrix and has not been checked frame by frame. The pull height uses the rocket model's top when one is baked, else the shared flyer default. The reticle's HUD style is the port's. The Endurance medal is not applied to rockets.

Remaining original-game acceptance: live launch/camera/control/audio comparison; exact launcher-offset reference frame; full flyer lateral inertia, high-pitch/roll/boost steering fidelity; exact collision-primitive dimensions (the port's rocket target sphere is provisionally 0.2 m, with swept center-line world collision); damage/crash transition and control-loss explosion timing. The port reads flight limits from the map and supplies them to the shared flyer environment. The original guided rocket's distinct 2.17-second outside-boundary expiry remains open. Main's separately owned portable-turret implementation is merged; its soldier acquisition/retention respects cloak visibility and rocket sweeps include deployed turrets. The cards remain open for original-game acceptance, even though the local implementation and available checks can be completed.
