## Guided turning follow-up

The maintainer confirmed the guided rocket works but reported jittery/laggy turning. Read the playtest black box first and froze local copies before further play could rotate them: engine/artifacts/equipment/jitter-snapshots/prev1.json, BF2 COR1, Conquest, seed 132, build 577d409e9bff, tick 1518. The checkout HEAD was the older main 42c31eb; the snapshot is interpreted against its actual binary commit 577d409. About 75 FPS, mean 13.34 ms, p99 15.44 ms; mouse aim is active. The snapshot does not sample per-frame rocket rotations, so it establishes build/input/performance context rather than proving a camera trajectory by itself.

Cause proven by a failing behavioral test on that implementation: `Sim::look_preview` entered the guided branch while MOUSE_AIM remained set, including zero pending mouse motion. It called a full 1/30-second steering prediction, then `Blend::preview` replaced the already interpolated rocket rotation with that absolute future pose. Rotation therefore advanced/held at simulation-tick boundaries instead of following the display fraction; its rotated chase-camera offset shared the error. With a constant 1.2 rad/s turn at 60 Hz, the reproducer drew yaw -0.0755523 rad at the first tick boundary where interpolation required 0.

Fix: guided rockets keep their existing interpolated pose and camera; remove the full-tick mouse-preview override. Their actual mouse-to-turn-stick routing, authored rate/filter, flight, collisions and controller-only simulation are unchanged. Foot, recon-droid and vehicle look previews retain their existing paths. This preserves the rocket's steering inertia and fixed-tick gameplay while drawing turns at the display rate.

Regression: actual authored rocket class, continuous turns at 60/75/144 Hz, mouse and controller inputs, pending and zero mouse deltas; compare the rendered angle to elapsed sub-tick progress, require monotonic turns and compare every post-draw simulation hash with an unrendered reference. The existing camera/position restoration test is updated to require that guided input does not fall through into soldier mouse preview. Original-game acceptance items above remain open; this follow-up does not claim an agent-operated interactive or PS2 test.

Follow-up checks: 1,143 release core tests and 463 release game-library tests passed (2 ignored); gameplay suite 260 passed, 1 ignored, with only the existing Mygeeto 0.3-second position-build timing assertion failing under parallel load (1.027 s). That test uses wall time on Windows because /proc/thread-self/stat is unavailable; its isolated rerun passed. The new six-configuration turning regression and all other gameplay checks passed. Formatting and diff checks passed. Local logs: guided-jitter-before.log, guided-jitter-checks.log, guided-jitter-isolated-timing.log.
