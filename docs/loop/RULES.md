# Engineering lessons (distilled from JOURNAL.md “Lesson:” lines, 2026-10-08)

These lessons preserve measurement and review discipline from earlier work. Current execution and landing instructions
are in `AGENTS.md` and `docs/agents/`. Dated receipts remain evidence for their named checkpoints.
References below to launcher lanes, claims, planner ranking and old `loopctl` commands
are historical explanations; those mechanisms are retired and do not govern new jobs.

## Top 10 (violated most often)
0. A gate that refuses a landing on a number the card was not about is a question, not a verdict: sort it NOISE / EXPOSED / CAUSED with evidence before blocking. EXPOSED (already on main, the card only sends more units into it - one traced case on main) = the card lands and the old bug gets its own card; you never approve your own claim - block the card `resume=EXPOSED-CLAIM ...` and an independent reviewer judges it (the maintainer, 2026-10-11; BSPN / DAGS).
1. Never claim "no class / nothing / never / 0 callers" from one tool: search the signed hash form, the call graph, ELF `jal` words, ALL worlds (incl. unbaked Ewok/wampa sides), the full untruncated output (L84 L89 L99 L103 L182 L192 L255).
2. A card's named cause is a hypothesis: re-measure the symptom on TODAY's main and trace one case before building the remedy (L5 L98 L145 L160 L231 L244 L248 L254).
3. Every instrument/test needs a control: a null variant equal to the parent hash for hash, or a mutation check; a test that passes under its own mutation referees nothing (L27 L49 L125 L146 L173 L180 L209 L230 L237 L242).
4. A headline number needs its baseline: rebuild the PARENT and measure it with the same instrument, plus a random/unaffected population (L51 L98 L149 L178 L200 L205 L252).
5. Own a dispatched job through its completion condition. Use `agent_job.sh status` and `agent_job.sh wait` to collect its exit status and final report (L1 L58 L69 L111 BF1BK).
6. Before resuming or landing, inspect the job service status and landing queue. Preserve live workers and another contributor's ownership (L41 L47 L71 L108 L130 L163 L239).
7. Never `pgrep -f`/`until ! pgrep -f` a pattern that appears in your own command line; poll a pid or a log marker (L7 L49 L161).
8. Sweeps are chaotic: one seed or 4 maps is not evidence; run all 32 maps, >=8 seeds (24 more to confirm a drop), judge paired per-seed/per-spot differences, not single-map finishes (L48 L49 L92 L169 L223 L250).
9. The branch gates render the SHARED bake: bake-carried changes show goldens/parity only at land phase 1; score with `--bake <scratch>` or an overlay first, and expect stale-bake DIFFs (L16 L45 L63 L88 L95 L117 L168 L208 L211 L213).
10. Read the live PS2 data (RAM, ELF constants, the disc's own tables) before fitting or theorising; predict from ELF constants first (L12 L80 L97 L115 L122 L186 L196 L247).

## RE and absence claims
- Before building on an RE doc's summary bullet ("a soldier never attacks X"), open the matrix cell or call it summarises: re-soldier-ai 4.4's "never a flyer in the air" was a weapon-chooser call on both branches (AUDIT HVYW).
- Before RE on "the port does not draw X", run the skip census on BOTH render paths (a battle merges the COMMON bake; pose_render / gallery stills did not until SKIPC): the console and droids were drawn in every battle and missing only from stills (SKIPC).
- To prove the PS2 draws an effect, empty its manager's active list in live RAM for one grab and diff the two frames (godrays: `lead_tmp/re/skipc/ps2/skipc_walk1.py --knock`, 10 minutes) (SKIPC).
- Check a rider's or any attached object's placement on SAVE STATES (written between frames), not on live RAM rows alone: live rows tear mid-update (a bike rider 1.3 m off his bike in 13 of 59 moving rows, 0 of 12 states) (VRIDE).
- Before fitting a vehicle's visual numbers to the stick, read the input function's caller for a remix and fit with and without it: BF1 turns a strafe into a turn when the class has no StrafeSpeed (fit 194 -> 244 of 276) (VRIDE).
- Before building on a baked clip's root motion, check the GLB track: the soldier clips are baked in place (DummyRoot has no travel); the ground per cycle comes from the bake's `root_speed` (ANIMM).
- Ghidra prints hashes >= 0x80000000 as `-0x...`; search both forms (or `veh0/hashloc.py`). Disc searches: `/usr/bin/grep -a`, the shell `grep` skips binaries (L84 L99 L182).
- The Ghidra export has holes (vtable-only/dead functions); scan the ELF words and name classes by RTTI/ClassLabel ctor, not neighbourhood (L103 L104).
- Absence needs `re_check.py absent`, a program-side count (not a `cut`-truncated listing), and a second reader; a one-reader census is not a census (L176 L192).
- Check which worlds/missions load the class before saying a behaviour is missing; class defaults are constructor CHAINS; REPLACE handlers can be called by other handlers (L87 L249).
- A formula holds only for classes somebody timed: derive per-class values over EVERY class and map; one sample with all classes beats two fixtures (L236 L251).
- An RE-doc `[H]` gets built as a guess: settle it with a RAM read or a 2-minute live sample before building (L203 L247).
- Verify the instrument's column and a borrowed script's meaning (stick direction, `floor_dy`, `team`, pad names) before building toward them (L137 L173 L197). A sign fed by a stick is checked on the PS2 rows (stick against the angle's rate) before building: BF1 and BF2 turn against the stick, so BF1's "raw stick" and BF2's "rate over speed" lean opposite ways (VTURG).
- Soldier slots recycle between save states; "does X change over time" needs a live sampler by the game clock (not update counts), last RAM read per tick (L13 L30 L120 L218).
- Mind PS2/PCSX2 artefacts: EE FPU rounding (emulate, no tolerance), reseeded LCG, per-game clip clocks (BF1 N/30, BF2 (N-1)/30), recompile-on-load (L33 L60 L64 L17).
- Run the verifier on RE claims BEFORE writing cards/docs; hand it scripts as well as claims; a dead session's draft is a claim list, not a finding (L21 L112 L170 L203).
- Knock-outs/knock-ins in live RAM (zero a field, patch a class prop) settle "which term makes this look" faster than reading the renderer (L62 L74 L75 L90).
- Before building toward a PS2 rate, split it per life and by distance on BOTH sides (where a bot dies, how near the enemy, what state) and knock the suspected cause INTO the port behind a switch; a rate can be a product of the PS2's own dullness (FGHT2).
- Check a PS2 pointer column against its type word before calling it "the target": the aim field holds a stale entity under aim types 1 / 2 and a seat under the board order (FGHT2).
- A PS2-against-port RATE gap: split it into time firing, shots a second and damage per shot on both sides before opening a function (`lead_tmp/clse/tools/run_w.sh`, 4 minutes); never referee a BF1 change with a BF2 table - take that game's own PS2 rate (CLSE CLSE2).
- "Whose field is it" (a tracker block "the target's"): read the block's owner word in RAM, or write the class field for ONE team and compare the two teams inside one capture - the other team is the control (CLSE CLSE2).
- An instrument that reads "no error" needs its zero: zero the suspected term on the PS2 and read the instrument's own constant first (0.06 m for the aim miss) (CLSE2).
- Before landing a named deviation from a PS2 key (class against weapon, team against unit), census both keys over every class on both discs and name the fielded classes they differ on (FGHTA).
- A spot where every bot sticks: count the lives that CROSS it on parent and main, then walk the PS2's own soldier through it both ways (`lead_tmp/tgap/tgap_probe.py`) before touching collision or steering; give each live PCSX2 session of a job its own name (OBSR TGAP).
- Save a PCSX2 state of a live battle before any wait of more than a few minutes and reload it for follow-ups: the battle ends on its own and its RAM goes with it (FAMB).
- A PS2 bot's current leg is its path FOLLOWER's (node come from / node walked at, `lead_tmp/mouth/tools/pathscan.py`), never the path object (the planner's state, a median 114 m away). A detector the PS2 cannot feed (the steering's `stop`) gets a twin both sides can, with the two's overlap printed on the port (MOUTH).
- Before reading a PS2-against-port damage RATE per aimer-second, print the damage BUDGET per unit-second by weapon in hand and the shots by band of the weapon's own MaxRange (`lead_tmp/clse4/tools/wbudget.py`, `wdist.py`): a rate hides the aimer time, and a weapon that never fires past a range names a gate. A constant commented "placeholder, no RE" under the rate you chase is the first suspect - read the class field in a capture's RAM (`wclass_burst.py`, one minute) before any sweep (CLSE4).
- A live sample cited for a PS2 rule prints the ALTERNATIVE rule's expectation and p beside it (Hoth's 11 / 9 / 6 fitted both spawn rules); before a new PCSX2 run look in `lead_tmp/mouth/ps2`, `dags/ps2`, `clse/ps2` - captures other cards made settled the spawn rule in minutes (BSPN audit).
- Where the port reads a post's property from the world data, run `strings` over the map's mission scripts for a run-time `SetProperty` of that key (20 of 128 BF2 scripts carry `spawnpath`; Kamino's conquest script moves cp2's) (BSPN audit, SPTH).
- A card that says "the port's body cannot X" from a bot's trace is two questions: walk the PLAYER through X on main beside the PS2's own walk first (`lead_tmp/skirt`: 24 walks both sides in 10 minutes; 6 of 14 already worked). A PS2 speed or "steady climb" read off 10 Hz samples is a hypothesis - sample every update (the last read before the clock moves) before fitting a rule (SKIRT).
- An RE answer "the port lacks rule R": knock R into a scratch binary and run the card's own bars before writing the build spec (the body rules alone gave the bots nothing while the steering kept them off the face). A knock-OUT that cures one map gets the sweep of the maps the knocked-out rule was built for before it goes into a card (no steep probe: hub 46 52 -> 31 stalls, tat1 + both Geonosis recycles 9 -> 26) (SKIRT).
- A stall site at a doorway: list the map's `base: "door"` instances and replay the PS2's passes through that door (`lead_tmp/mouth2/tools/doors.py`, `doorpass.py`) before any route hypothesis. A bot standing with `stop open, steer fwd` and no speed is its BODY, not its plan: print it every tick (pos, vel, grounded, floor normal, the wall pass's push and its triangle) before touching steering or routes (MOUTH2).
- A PS2 BF1 capture's team 3 is the map's natives (one side's allies): contact / enemy tests on teams 1 and 2 only (`lead_tmp/clse2b/tools/ps2_bf1_contact.py`), and reproduce a number the RE doc already has before quoting a new one (20.7 % was 5.2 %) (CLSE2B).

- "Only X and Y write this field" needs the ELF's count of `jal` words to the writer (`re_check.py absent 0x0c<target/4> --elf`), not the export's callers: a jump table the export could not recover hid four of six calls of the aim error's add (CLSE2 audit).
- A RAM fixture for a formula keeps ALL pool rows and prints the share that fits (one filtered by the formula it tests, 80 of 112 kept, cannot fail). A PS2 rule that runs every N updates: sample every game update (the last clean read of each clock value) and feed the rows to the PORT's own function in a scratch test - `lead_tmp/audit-clse2/ps2/block_live.py` + `tools/mk_replay.py`, 44,000 thinks in ten minutes (CLSE2 audit).
- "Which clip plays in direction X": read the animator's state setter and the pose function's case for that state BEFORE any clip census (the picture may be one clip plus a bone turn), and take one live row set of the animator block per direction. A "no such clip" census by candidate names includes the bank-named families and compound words, prints the expected chance hits and resolves every odd hit; an alphabetical, fully named bank needs no list (ROLLS).
- A PS2 picture strip: `ffmpeg -f x11grab -use_wallclock_as_timestamps 1 -t S -i DISPLAY` (`-t` BEFORE `-i`), check the first file's size before the batch, pick frames by the row's game clock less the trial's picture lag (BF1 0.05-0.09 s, BF2 0.12-0.22 s). A pad steering loop's yaw tolerance is over half the stick's one-update step (BF2 2.2 deg, BF1 1.6), or it ping-pongs (ROLLS).
- Before building a card's rule for "bots at X": count every MEETING of a bot with X and what follows in 3 s (`lead_tmp/doors/tools/waits.py`) and sort the stalls near X by cause (`classify.py`) - 48 % of the stalls near doors were bots standing in a firefight, 30 % a path corner in a wall. A count read off a tool's example list is a floor (a list cut at 6 read "8 of 32" where it was 31): count in the program (DOORS).
- A census that sorts weapons by NAME prints the code's own class beside it: `rep_weap_inf_rocket_launcher` is a missile launcher in BF2 and a bullet rifle in BF1, and 75 % of the "rockets at a lone soldier" were three person weapons (HVYW).
- Before a card promises a behaviour for a named weapon, list the class's slots and channels through `roster::held_slots` (a scratch test, one minute): the wrist rocket's rule was tested on a fixture while no soldier of the port held one (HVYW).
- Before writing "the PS2's HUD has no X" from layout data, take one PS2 frame of X happening (5 minutes from a no-AI state): BF2 draws ten HUD pieces from code, outside the `hud_` chunks. A rule read from code for an on-screen object is replayed over ALL of the PS2's own rows as a reference implementation before the doc is committed (`lead_tmp/cpbar/tools/replay.py`: 4,332 of 4,338; the first run's misses were the lag test, not the rule) (CPBAR).
- A picture cannot prove "not drawn": read the object's in-scene flag in RAM (BF2 soldier E+0x118) and print the row (pilot word, health) beside every frame cited as "manned". A receipt for "no class authors key K": list every class key hash of the disc (`lead_tmp/vturd/allkeys.py`) and run `re_check.py absent --src` on the list with one present key as the control (`--src` on raw LVLs searches ASCII only). A "which node / bone moves" finding becomes a build only after counting triangles across bones per model (`lead_tmp/vturd/softcensus.py`: 0 = rigid parts moved like doors, else the skin path) (VTURD).
- Live PS2 trials: an actor placed beside the player is proved by the game's own count first (a soldier slot is re-used by the other team; a BF2 soldier parked 400 m up does not come back alive); raise the player's MAX health, not only pin it (a detonator kills through a pin); a per-update sampler re-reads the game clock after its reads and drops the row when it moved, or a few rows in a hundred are torn (`lead_tmp/vturd/ps2/turret_b1x.py`). Resuming a died session: `pcsx2_session.py list` and stop its emulator, then replay its stored captures against its readers' formulas before sending new readers (CPBAR VTURD).
- Name a PS2 voice line by its PROPERTY (the gate's `next` in RAM, `lead_tmp/usnd/ps2/usnd_live.py`), never by its audio segment: takes are shared, and three of BF1's six "combat calls" were heard only as another call's take (USND).
- Take a BF2 voice baseline with the player INSIDE the fight (`usnd_live2.py --follow 20`): a line needs a speaker within 50 m of the player; a capture that keeps the player alive raises health AND max health (30000) and re-finds him at most every 1.5 s (USND).
- Back a "no code calls this vtable slot" claim with an ELF scan of `lw rX, off(rY)` + `jalr rX` sorted by where the vtable is loaded from (`lead_tmp/usnd/tools/vcall.py`) and one live "never armed" read (USND).
- Print a per-family data value per faction from the census file before it goes into a claim: the first rows of an alphabetical listing stood for four armies, three of which differ (USND).
- Before building a nine-pose / clip-blend rule, dump the baked clip's frames against each other (`turret_gunner.rs dump_seat_clip_frames`): the dish clip's three pitch rows are one pose, so a control "frame 7 is not frame 4" only discriminates on a clip whose rows differ (VTURG).
- A card's bar that quotes an aggregate over a selection ("47 quiet hovers") is a draft until the selecting script sits on disk beside the numbers: re-run it before the bar is quoted (VREST's 1.32 -> 0.71 cm reproduced under none of 90 selections; HSTEP, AUDIT HSTEP).
- A chunk census walks INTO `modl` and the other content chunks, not only `lvl_`: a top-level walker found 0 of 404 `shdw` chunks (FXC).
- Before naming which class key attaches a part, scan the ELF for the key's hash and read a live soldier's attachment list in RAM: `ClothODF` is never read, the gmod INFO list attaches cloth. A "two-sided" draw on the PS2 is the material word's VU1 cull bits (0x800800), not the stream order: check the caller's vertex count before reading a vertex callback as "drawn twice" (CLOTH).
- Search a hash >= 0x80000000 in Ghidra's 64-bit form too (`0xffffffffXXXXXXXX`; `re_check absent 0xXXXXXXXX` misses it) and scan the ELF for lui/ori builds (`lead_tmp/re/lod/tools/luiscan.py`), not only whole data words: GeometryLowRes read dead for three weeks (LOD).
- Before building on an RE doc's one-word gloss of a condition ("its first path leg fails"), open the predicate it names: UTALK's was "inside the goal's radius", another moment (UTALK).
- A census of mounted / attached soldiers taken through the collision world misses every one the game took out of it (riders inside a hull): enumerate through the member pool or one live row per update (RIDK: 7 of 11 riders unlisted).
- To prove which LOD (or any per-object pick) the PS2 draws, swap ONE gmod's slot or count in live RAM and grab twice with a control after the restore; a poke at 0.6x / 1.6x of a formula's switch value tests the formula in one boot (LOD).
- Hand a workflow its claim list as a JSON object in `args` and make the script throw at once on a missing or string-typed field: a placeholder string started 7 verifiers on empty claims (RIDK).
- Before trusting a sky key's documented slot, read the slot in RAM across every reference state: a per-frame HUD draw set BF1's CharacterAmbientColor flag, so three maps keep the reset's 128 instead of AmbientColor (SBLT).
- To separate a light term's form from pose or geometry, sweep the light's direction in PS2 RAM (behind / overhead / front / both sides) beside the port with the same knob: one real-sun number mixes form, scale and pose (SBLT).
- Before building on a class's size key, check whether the port poses that class on its own rig's bone lengths at all: the soldier clips carry the human bank's translations onto every bone, so a missing scale can hide a missing skeleton (USKN).
- Before writing "game X draws Y" from a call site, open the vtable slot the call goes through and read its code bytes in the ELF and in one save state's RAM: BF2's shadow draw was a 3-instruction stub behind a live gate (VSHD).
- To pin a PS2 full-screen pass's strength, poke its prebuilt display list's register word in live RAM (the A+D pair by register id under the list pointer) at 0 / full / half and score each frame against the gate-off frame: one run gives the factor, the exact region and the ruled-out alternatives (VSHD).
- Before calling a field's flag dead from a byte-offset search, search its word-index form too (an int* parameter writes +0x660 as *(decompiler detail omitted)*); and before trusting a baked path name for a lookup the PS2 does by hash, count duplicate names in the manifest (BF2 KAS2 / YAV1 carry two `boundary1`; the PS2 takes the first registered) (BNDY).
- Before a live hold, probe the save state's human member for a soldier (BF1 member+0xb4, BF2 record+0x148; `lead_tmp/bndy/tools/probe_states.py`): BF1 KAM1 / HOT1 / YAV2 walkabout states hold none; and a disc census by LVL name scans the map's own directory (BF1 `LOAD/YAV1.LVL` is a loading screen) (BNDY).
- Before calling an agent's or class's function an export hole, lay its vtable beside a sibling class whose slots are known (`lead_tmp/gunwt/tools/agents.py`): GUNWT's "hole" at slot +8 was the empty exit and the update at +0x38 was decompiled (GUNWT).
- When two verifiers split on what a field gate means, settle it with a split RAM census over every save state (on foot / seated, AI / player), finding each sub-object's offset the way the code builds it; one reader's reading is not the answer (GUNWT).
- Before calling a PS2 movie or stream silent, count its MPEG private-stream-1 (`00 00 01 BD`) packs: ffprobe does not list Sony PSS audio. In lifted Lua 5.0, read which register a CALL's results land in before reading the op that uses them (two BSHL misreadings came from the lifter's names) (BSHL).
- Before calling an odd PS2 camera value a separate mode, check whether it is one step of a known ease frozen by a camera switch (target + (v0 - target) e^(-k dt)); a staged PS2 enemy kill puts the player beside the team-mate nearest an enemy (`lead_tmp/ssel/ssel_live2.py front`), never at an empty teleported spot (SSEL).

- Before porting a PS2 eligibility rule (unlocks, limits) into the sim, open every caller's controller gate: `FUN_00364290` binds humans only, so bots and the sweep stay untouched (SSELB).

## Perf and determinism
- Before landing a search that runs inside a sim tick, print its per-call cost distribution over every map (`lead_tmp/retw/tools/costbin.sh`, one stderr line per call): the first floor search cost 162 ms worst case, the A* 16 (RETW).
- Quote a per-tick cost only from runs made one at a time (`lead_tmp/obst2/tools/perf.sh`, JOBS=1), 6 seeds or more, with a null twin of main beside it: at 6 parallel jobs a copy of main read x 0.954 of main and the per-seed sd is 0.04-0.09 (OBST2).
- Run an iGPU frame timing only when the 1-min load is under ~8, with a control repeated in the same batch, and check the run's OTHER sections against a known clean run before quoting one: the other lane's CPU load slows every GPU section 35 % to 2x, the sky included (ISPF, ISPD).
- Price a shader cost with variant WGSL files read by a scratch binary (`OPENBF_X_SHADER`, `artifacts/ispd/x/scratch_env_shader.diff`), one change each, before writing a build card (ISPD).
- When a cost run's null twin reads sd over 0.1 (the other lane's sweeps), repeat it and quote the best reading per seed over the runs, main's twin counted as main - and say so beside the number (OBST2).
- Judge a frame-time hitch by the main thread's run-queue ms (the record's `queued`) before blaming a phase - under load a 1 ms draw-list build reads 43 ms; run windowed timings in a private kwin_wayland (`lead_tmp/hitch/tools/krun.sh`), never Xvfb on the RTX (35 ms a present) (HITCH).
- Run a windowed frame-time A/B only interleaved (A B A B) with the runnable count logged beside each run: one GEO1 binary read 15 and 307 frames over 25 ms minutes apart while an audit swept (HITCH land).
- Profile with `perf` (flat) and `valgrind --tool=callgrind` (callers; `perf --call-graph dwarf` fails here) on a copied release binary, quoting instruction counts and shares, not wall clock under load (the maintainer, 10-21; HULLC).
- Sim-only per-function cost = callgrind(N ticks) minus callgrind(1 tick) of the same binary (`--toggle-collect` on a Rust symbol collects 0); price a profile's rest of the list again after its top item lands (HULLC).
- A bound that answers a per-sample query still pays the per-sample lookup: skip whole samples (a run length the bound vouches for) or the saving is a few % (HULLC).
- Before building a presentation-only change, add its measuring column to the frame CSV and A/B it on ONE binary with an env switch (same machine, same seed): the off switch is the baseline (RINT).
- Before pricing a per-fragment switch (dither, discard band, shader variant), census on the CPU the draws per light path and the draws whose every fragment the shader discards: a droppable draw costs a full raster on a weak GPU, and the paths a map really uses decide which variants pay (LODP, ISPS).
